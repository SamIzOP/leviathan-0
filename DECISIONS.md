# Engineering decisions

## Foundation decisions (historical; later scope sections supersede them)

- Foundation only: no guns, combat, damage model, robot combat AI, progression, real levels or final art. Placeholder motion and a development dummy are the explicit exceptions required to prove synchronization.
- TypeScript npm workspaces, plain DOM, Vite/Three.js, Node/ws and Zod. Server bundled with esbuild; shared TypeScript is bundled into both targets so production Node never imports `.ts` sources.
- Node 20.19+ minimum; Node 22 Docker runtime. Lockfile committed for reproducibility. Test runner updated to a patched 4.x release after dependency audit.
- JSON wire format is confined to shared codec. Protocol version is 1. Same-origin browser WebSockets, 16 KiB limit, per-connection rate and malformed-message limits, bounded queues and backpressure. Capacity is 512 sockets / 1,000 rooms per process.
- Input commands are absolute button masks; jump is an input edge. At most one command advances a player per simulation tick. Redundant recent inputs mask injected packet loss; monotonically increasing sequence numbers deduplicate them. Missing input uses zero axes with gravity. The server never accepts positions or client-selected elapsed time.
- Simulation uses a high-resolution accumulator, fixed dt, 250 ms catch-up cap; snapshots have an independent accumulator. Configured rates are announced in the handshake.
- Client replays unacknowledged inputs and decays visual correction over 75 ms. Remote entities interpolate 100 ms behind receipt-adjusted server time. Artificial `lag` means round-trip milliseconds (half on each direction); `loss` drops gameplay messages for testing, although WebSockets normally provide reliable delivery. Loss telemetry estimates missing snapshots, not network-level TCP packet loss.
- Collision has a floor and axis-separated boxes; this is deliberately a simple shared placeholder, not advanced movement. View/body state uses world units in meters and radians.
- Names use a replaceable, small substring blocklist, whitespace normalization, basic leetspeak normalization, and case-insensitive suffixes that preserve the 16-character limit. UI uses textContent and canvas text.
- Disconnected slots remain reserved for 45 seconds; host migration happens on explicit leave or grace expiry, preserving the reconnecting host's place. Tokens are cryptographically random 256-bit secrets, never included in public views/snapshots. Newest valid token connection supersedes the previous connection.
- Session storage wins over local storage; this allows independent existing tabs with separate sessions. A newly opened tab resumes the most recently saved local session and replaces its older connection. To create a distinct second operator, use another browser profile/private context or explicitly Leave first.
- Voting lasts the full configured window. Most cast votes wins, host breaks ties, absent host vote defaults replay; nobody voting defaults replay. Enough connected operators starts a fresh countdown automatically. Otherwise return to lobby. Empty rooms are retained another 60 seconds after the last reserved slot expires.
- Seven mission labels represent six factories plus VANE SS; NEXT wraps after the final label. All use identical arena geometry now. Results contain elapsed seconds and connected operator count, not fabricated combat statistics.
- Debug F8/F9 requires DEV_TOOLS and host ownership. The solo/UI update below supersedes the former independent DEV_SOLO flag. Dummy caps at 16 entities, wanders only on the server and has no combat behavior.
- Audio manifest is fetched at runtime from public/audio, permitting file swaps without TypeScript edits. Missing files are cached as unavailable for the page lifetime. Volume buses include a future voice bus but no voice transport. Rain is filtered looping noise; other fallbacks are short tones. User interaction unlocks the AudioContext.
- No cloud credentials or repository destination were provided. Deployment is prepared with Docker and Render Blueprint, with account/repository authorization documented as manual. In-memory sessions intentionally do not survive process replacement; horizontal scaling is deferred.
- Browser verification uses Playwright; the optional CHROMIUM_PATH supports an already-installed Chromium. No browser download is needed for ordinary play.
- The host can choose OPEN LOBBY during results to admit new operators between matches; this cancels the current vote and clears ready states. Otherwise the vote automatically starts the chosen rematch.
- Input simulation runs on a separate fixed-step timer from rendering, so slow drawing does not reduce command rate. Routine ping updates preserve menu controls and settings focus.

## Scope-locked solo / 2D interface update

- Exactly the requested solo/developer tooling and 2D visual restyle. No combat, movement-system redesign, arena geometry/material/lighting change, new level, deployment change, commit or push.
- One server flag: `DEV_TOOLS`. A separate development entry point supplies true only when the variable is absent. The production entry point requires the exact environment value `true`; client URL/localStorage claims cannot grant access. An explicit false overrides the development default. The legacy hello `dev` field remains for compatibility; the new UI trusts only `devTools`.
- Additive messages only: `dev-solo`, `dev`, `dev-state`; `hello`/`welcome` gain `devTools`. Existing command fields, input transport, snapshot semantics, normal timers and reconnect grace remain intact. The earlier core-test fixture uses the replacement flag; its twelve tests retain their assertions.
- The requested movement sliders conflict with a literal ban on any simulation parameter adjustment. Resolved narrowly with a dev-only synchronous adapter around the unchanged shared movement function. It saves/restores constants in `finally`, with room-local tuning and identical client replay. No async work occurs inside the adapter. The original `movement.ts` SHA256 remains `CE1D1C69F6361EF75DDB7E099F7D6E78D561AF23A025F23322A9FDE5F1A27491`.
- Empty solo callsigns use TESTER automatically, avoiding a blocking prompt. Solo refresh uses the existing token/identity and enters the arena immediately. A browser user gesture is still required for mouse capture; the small click hint is not an entry menu.
- Synthetic players have real player entities, queues, ready flags and room slots, with no-op server-local peers. Their ping is zero. They are test input generators, not combat AI. Host migration selects the oldest remaining human, and the last human's removal clears synthetic slots. Existing wandering dummy behavior is reused unchanged.
- Device-local draw toggles, fault sliders and section expansion persist. Timer/freeze preferences are saved locally, while the server's current room state is authoritative after refresh. A new solo room always defaults to timer disabled. Tuning persists only for that room's lifetime, not across server restarts or into production.
- Debug drawing is a separate Canvas overlay. The self ghost also has a top-down inset because a first-person camera often cannot see its own authoritative body. F3's original telemetry text and calculation remain unchanged.
- Menu panels are opaque, square and high-contrast; gradients exist only in the procedural background. Settings use an independent drawer so short desktops remain usable. Long rosters and expanded developer sections scroll within bounded panels. Preloaded local font files and licenses come from the installed Fontsource packages.
- The dead-street art is a stylized procedural illustration, with optional local WebP/JPG replacement. Rendering is capped, hidden-tab aware, reduced-motion aware and released on match entry. Measured Canvas command submission time is documented separately from GPU/presentation performance.
- Outside scope and left untouched: the original spawn can face/stand close to a box, close 3D name tags can occupy much of the view, and the original F3 two-second snapshot average initially reads below the target rate. The build's existing large Three.js bundle warning remains; no code-splitting or deployment work was added.
- The original browser harness's generic `summary` selector now targets the settings drawer specifically, because the requested developer sections add six more summaries. Existing workflow assertions remain intact. Entry-field values are preserved through handshake redraw, and Enter explicitly submits the callsign field.
- Mouse-capture correction: button presses use the independent CSS `translate` property to preserve the capture hint's centering transform. Clock-only PLAYING updates no longer rebuild the interface; the frame loop still reads the current deadline. This prevents solo/frozen timer heartbeats from replacing a pressed button.
- Embedded-browser capture failure is handled locally: after a rejected request, explicit play activation enables keyboard movement and left-drag look. Escape, window blur, overlays, and leaving gameplay clear fallback input. Native pointer lock remains preferred. This changes input availability only; movement simulation and networking are unchanged.
- Vote selection reflects the local player's server-confirmed vote through `aria-pressed`. Neither option starts selected, and hovering an unselected option does not use the selected fill. REPLAY remains the server default when nobody votes.
- The browser regression waits for document readiness on resumed tabs, then asserts the actual game phase and identity. A single bounded retry handles Chromium's occasional initial `ERR_ABORTED` after restoring an offline context; all application assertions remain. The final passing run required no retry.

## World / look stage (supersedes diagnostic-arena-only statements above)

- Scope is world geometry, rendering, weather, optional local assets and environment audio. No weapons, health/damage behavior, combat AI, objectives, pickups, new menu screens, deployment, commit or push. Existing capsule entities, pointer-lock fallback and exclusive vote selection remain.
- `stepPlayer` is untouched. Its original jump impulse 7 m/s and gravity 20 m/s² give 1.225 m ideal jump height. Authored jump-chain rise is at most 0.8 × 1.225 = 0.98 m. The conservative reachability graph also limits horizontal gaps using existing sprint speed and ballistic flight time. Structural chimney/column tops are not playable platforms; all usable roofs/catwalks/containers are included. This graph proves connected platform routes, not an exhaustive continuous collision-path proof.
- Shared design metrics use 1.8 m height, 1.65 m eye and requested 0.4 m radius clearance. The existing collision radius remains 0.35 m to preserve movement. PHYSICS.arena changes from 24 to 70 solely to accommodate the requested 140 m world boundary; no movement integrator/tuning changes were made.
- Factory 2 is the same collider/decor layout with heavier, colder weather. Later mission labels reuse the two variants; distinct later factories remain out of scope. Spawns are spaced in the street and selected against occupied positions. Future traversal flags and enemy/pickup/objective markers are inert data.
- Production DEV_TOOLS remains off by default, including solo/camera/perf URL entry. Existing diagnostic getters remain read-only; camera controls are gated. GPU timer support is optional and explicitly reported as null when unavailable.
- LOW runs at native viewport resolution and uses 512 px surface maps. MEDIUM uses 1024 px, HIGH currently also uses 1024 px procedural maps (below its 2048 cap). Small ornament distance reduction and bounded instancing preserve the main silhouette. HIGH road reflection is optional; it is disabled outside the street. Texture memory readout estimates surface maps only, not driver allocation or framebuffer memory.
- No external art is downloaded. Runtime HEAD checks reject HTML fallback responses; failed loads retain procedural art. Models may need bounding-box-consistent authoring to match the AABB approximation. Asset credit records are required when third-party assets are later supplied, as described in ASSETS.md.
- Software-rendered inspection exposed blocked yard/stack cameras, stretched wall roughness and sky clipping. These were corrected and all eight views were recaptured and inspected using Intel UHD / ANGLE D3D11. Wetness is projected in world coordinates; rain/ripples are suppressed indoors. The van remains deliberately blockout geometry with silhouette-matched glass, wheels, seams and bumpers.
- Out of scope and unchanged: combat systems, advanced traversal, distinct later mission geometry, cloud publication and production hosting limitations documented in earlier stages. No additional player setup is required for this stage.

## Six-goal world revision (supersedes previous movement/scale restrictions)

- This revision explicitly authorizes shared grounded step-up and snap-down, plus a shared broadphase. It adds no slide, wall-run, double jump, mantle, sprint changes, combat, AI, pickups, objectives, menus or deployment. No commit or push.
- Design clearance remains radius 0.4 m; the existing movement capsule radius remains 0.35 m. The permitted 0.5 m grounded step is distinct from the unchanged 0.98 m maximum authored jump-chain rise. The outer numeric clamp expands to 120 m; visible compound geometry confines actual play to the 220 × 180 m level.
- Stair flights use 0.17–0.19 m risers and 0.29 m treads. Parallel switchbacks and landings beyond the last tread avoid head obstructions; individual tread plates replace oversized solid wedges. Two independent service routes reach the hall roof.
- The perimeter flood samples a one-metre grid with body clearance and step/jump ascent. Because a simple flood misses long descending jumps, real stepPlayer probes also test exposed elevated edges in eight directions. Crane access was moved inward and the hall roof gained visible three-metre rear barriers after this check exposed possible exits.
- The browser boundary test simulates 60 seconds of running/jumping in each cardinal direction for eight server-side players, and checks out-of-bounds/below-map recovery. It runs fixed simulation ticks faster than wall time; the separate reconnect stress test uses real sockets and wall time.
- Pointer-lock rejection, absent API and a one-second pending request all enable drag look. A dismissible browser notice remains available in pause/controls. Successful native capture clears it. Collider wireframes start off on each visit, even if previously saved on.
- Gallery rendering needed an explicit exception to the existing non-playing canvas visibility rule; visual review caught this despite passing DOM controls. The gallery test now asserts canvas visibility.
- Shared procedural surface maps reduced duplicate paint/facade texture allocation. Smooth painted metal uses a fine worn surface rather than corrugation on cars. Original sign text and serials require no downloaded fonts/models.
- Exported GLBs include material factors and UVs; game-generated canvas textures remain runtime recipes rather than baked external images. Collider matching is AABB-envelope matching, consistent with the current axis-aligned simulation; curved models do not introduce mesh collision.
- Outside scope and untouched: existing capsule players/dummy, later mission layouts beyond the two weather variants, combat systems, network protocol semantics and cloud hosting. The existing large shared Three.js chunk warning remains informational.
- Final visual review keeps the composition camera elevated at 12.5 m inside the entrance with an 84-degree field of view. The distant left water tower is 88 m tall so its silhouette clears the enlarged rows. Gallery metals use a neutral generated studio environment; van glazing sits outside the body shell, with split rear-door details.
- Escape is handled explicitly for native capture as well as drag fallback. A keyboard regression exposed reliance on browser-default unlock behavior; the final check uses an actual Escape key before recapturing.
- Optional model overrides cover both collider-backed props and decorative forge props. Verification loads generated container and water-tower GLBs through the existing manifest, without altering the saved manifest.

## Movement stage (supersedes earlier placeholder-movement statements)

- Scope is exactly the movement system: state machine, prediction/replication additions, input and settings, camera/audio/pose feedback, level traversal flags, Movement Lab, dev tuning/debug tools, harnesses and tests. No weapons, viewmodels, health, AI, pickups, objectives, voice, new menus, deployment, commit or push. The diagnostic dummy is unchanged.
- One pure function `stepPlayer(state, input, dt, world, tune = MOVE)` with all sub-state in `entity.move`; a fifth optional argument carries dev tuning, replacing the earlier dev adapter that swapped global constants. Production always uses `MOVE`.
- Hull radius is now 0.4 m, matching the specification and the level's design clearance (the previous collision radius was 0.35 m). The flood and reachability checks were already sized for 0.4 m and still pass.
- The placeholder jump (7 m/s, 20 m/s², 1.225 m) is kept as `PLACEHOLDER`/`basePlaceholderJumpHeight` for the validators, whose rules are unchanged. The new jump apex is 1.28 m. Jump impulses add half a step of gravity so the fixed 60 Hz apex equals the analytic height; without it the measured apex was 1.215 m, below the placeholder.
- The air jump is tuned to 6.9 m/s (specified "about 6.5"): with the 1.28 m jump, 6.5 m/s gives a total reach of 2.13 m, below the specified 2.2–2.6 m; 6.9 m/s gives 2.27 m.
- Wall-run sink speed is capped at 1.6 m/s after the 0.6 s rise. With uncapped 15 % gravity, any run started from a normal jump touched the floor after about 1.5 s, so the 2.2 s limit was unreachable. The harness measures the full run from an air-jump entry.
- Mantle height is measured from the feet at the moment of the grab, as specified. Consequence: from a standing jump the window reaches ledges up to about 3.6 m, from an air jump about 4.6 m. In the Movement Lab the 2.6 m wall is beyond the 2.3 m standing window (a jump press at its base does not grab it until the jump has lifted the feet); the extra 4.0 m wall is out of single-jump reach and needs the air jump. Holding crouch suppresses grabs and latches (that is also how a cancelled mantle stays cancelled).
- Sprint applies only with forward input; AUTO-SPRINT inverts Shift into a walk key. Slides start only from a crouch press while sprinting at ≥ 6 m/s; landing with crouch held at ≥ 6 m/s also slides (entry formula and cap as specified).
- Edge detection uses the previous held buttons stored in the state. The client sends held jump/crouch bits with one-command tap latches. Missing server input now repeats the last held buttons (axes zero) instead of releasing them, so input starvation can never fabricate a jump press.
- Prediction keeps a per-sequence history and reconciles only on mismatch (any sub-state field exact; position 0.1 mm, velocity 1 mm/s). Corrections still blend through the existing 75 ms camera correction. The tolerance covers last-ulp cross-engine `sin`/`cos` of yaw; all other per-tick math is exact IEEE arithmetic.
- Snapshot entities carry compact `motion` bits; each owner additionally receives its full `move`. Sending the full sub-state for every player to everyone would roughly double snapshot size. Protocol is now 2; tests and scripts that hard-coded protocol 1 use `CONFIG.protocol`.
- Level audit (data only): street facades, the two run walls, container stacks and hall walls are wall-runnable; hall side/back walls only on their interior faces through a new optional `runFaces` collider field (the exterior faces lead along the hall into the perimeter corridor). Roofs, roof-access plates, containers, crates/machinery, vehicles, barricades, catwalks, landings, bridges, stack bases and the boiler are mantleable. Stair treads lost their old blanket `mantleable` flag (step-up covers them); perimeter, gates, shutters, roof barriers and pillars carry no flags. Container tops are 2.6 m, above a 2.3 m standing window, but the specification lists them and a jump puts them in reach, so they are flagged.
- Perimeter seal: the full-movement search found 190 escapes out of 63,410 probes, all pure jumps (chained slide-jumps reaching about 12 m/s plus the air jump) from towers and roofs up to 28 m high within 17–20 m of the 12 m wall. Flags cannot stop a jump, so the smallest geometry change was added: four collision-only `clip` volumes stacked on the existing perimeter footprints from 12 m to 64 m. They are not rendered (debug collider wireframes show them); the visible 12 m wall, spawns, scale and confinement layout are unchanged. The search then found zero escapes.
- The level validators keep the placeholder jump chain and step-up rules. Their elevated escape probe now uses the real integrator with sprint plus a jump on every landing (no air jump), matching the old held-jump behaviour under edge detection. `level:check -- --advanced` adds an informational report of platforms that gain entry routes through mantle or wall-run.
- Movement Lab is dev-only: the development server entry registers it, the production server bundle never imports it, and the client imports it behind `import.meta.env.DEV`, so production builds and mission lists do not contain it. `dev-solo` accepts `level: 'lab'`; a plain solo restart returns a room to its mission level. The lab adds a mantle block after the long wall so the browser test can run one continuous chain.
- Horizontal FOV (80–110, default 95) is defined at a 4:3 reference (Hor+), i.e. about 78.6° vertical at the default, close to the previous fixed 75° vertical. The speed kick adds up to 8° horizontal.
- Left Ctrl crouch is off by default. When enabled, capture also requests fullscreen and Keyboard Lock where supported, so Ctrl+W reaches the game; otherwise the browser closes the tab, and the setting says so.
- Tests changed only where they encoded the replaced placeholder: protocol literal, the instant 5 m/s first step (now compared with one shared step), the 40-tick stair walk (now 50 ticks because walking accelerates), and the PHYSICS jump/gravity assertion (now asserted on `PLACEHOLDER`). `makeEntity` no longer embeds a movement state; it is created on the first step from the grounded flag, so states built only from flags behave as before.
- Out of scope and untouched: weapons/viewmodels, combat AI, the dummy's random wandering, the large Three.js chunk warning, and the existing browser-pane behaviour where a hidden preview pane stops animation frames.
